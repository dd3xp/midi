# Analysis companion: MIDI-to-amplitude diagnostics

This companion defines the fixed-prediction analysis in the manuscript. It supplies cached targets, note annotations, MIDI features, predictions from all eight internal predictors, exact fold membership, analysis code and a file-hash manifest. It is a local submission package; no public repository or public data release is claimed. The supplied NumPy program reproduces the numerical comparisons without training or a GPU. Historical recordings, training checkpoints and a complete historical software environment are not included.

## 1. Target and data provenance

There are 186 tracks: URMP 136, Bach10 40, PHENICX 2 and TRIOS 8. Piece identity and exact amplitude/pitch duplicates define 44 groups. `tracks.json` gives the original track identifiers, corpus, instrument, group, cached hop time and target hash. `folds.json` indexes this ordered track list, assigning training, validation and evaluation roles separately in each of four folds. Every track is evaluated once; no group crosses roles within a fold. Twenty percent of the remaining groups serve as validation. Split seed: 20260911.

Targets are the retained float32 amplitude arrays, without additional evaluation gain fitting or normalization. The archived preprocessing source specifies 16 kHz audio and `librosa.feature.rms` with a 320-sample window and 160-sample hop. That historical call leaves centering and padding at library defaults; its exact historical librosa version has not been recovered. The cached target arrays, rather than a claimed bit-exact reconstruction from recordings, define this study. They are not calibrated sound-pressure levels. Recording gain, room response, microphone placement and source separation can affect this target. A constant positive track gain does not change within-track Pearson correlation, but it does affect linear errors and may affect learning.

The archived corpus loaders select instrument-part files: URMP `AuSep_*`, Bach10 instrument-suffixed WAVs, and instrument-named PHENICX/TRIOS files. They average channels to mono and resample to 16 kHz before RMS extraction; they do not select ensemble mixes. This is source-path evidence, not a new acoustic isolation measurement. Bach10 has onset annotations; its loader constructs each offset from the next onset, with the last extending to the retained horizon. All 1,917 adjacent Bach10 pairs in the cache match that rule. Other loaders retain supplied note durations. These conventions affect interval means and preclude attributing the URMP/non-URMP contrast solely to corpus acoustics. Notes contain absolute onset, offset, pitch and velocity. Velocity is zeroed before extracting every input feature, including features that might otherwise depend on it. No audio-derived velocity, teacher amplitude or audio feature is supplied at inference. Performed timing is supplied, so this is not score-to-performance generation. Note-interval RMS averages describe the observed track envelope; they do not identify isolated-note acoustic energy. Overlap exclusion below checks annotation interference but cannot eliminate reverberation or recording effects.

## 2. Input features and predictors

The 20 feature coordinates, in zero-based order, are: activity; pitch/127; normalized note phase; log(1 + elapsed note time); onset proximity; offset proximity; local note density; preceding pitch interval; its absolute size; preceding rest; local pitch trend; rhythmic regularity; three instrument-family indicators; pitch position within track range; phrase position; relative duration; running pitch direction; articulation ratio. Context is computed from the supplied MIDI. Exact windows, clipping, overlap handling and boundary rules are in `source/local_run_20260912/source_snapshot/src/model/solo/dataset.py`, function `notes_to_frame_features`. The supplied feature arrays preserve the evaluated inputs.

Mamba uses model dimension 128, six layers, state size 16, convolution width 4, expansion 1, bidirectionality and dropout .2. S4D uses dimension 256, four layers, state size 64, bidirectionality and dropout .2. Both attach the same decoder design: a frame BiGRU, two Transformer layers with eight heads and feed-forward width 1024, and the existing note-aware amplitude head. Their total parameter counts are 7.66M and 8.59M. The independent standard BiGRU has two bidirectional layers, 256 units per direction and dropout .3; linear projections produce pitch logits and softplus amplitude, with 1.65M parameters. It was added after viewing the original results. This comparison is not an isolated ablation of the note-aware head.

Each neural run uses seed 42, batches of 32 random 512-frame crops, Adam without weight decay, initial learning rate .001, ten warm-up epochs, cosine decay to 1e-6, at most 300 epochs and patience 60. Selection minimizes validation loss on eight deterministic, equally spaced crops per track. Evaluation runs full tracks. Exact commands/configuration and model source are included under `source`; they document the frozen runs rather than a newly executed replication.

The loss is voiced-frame pitch cross-entropy plus twice the amplitude loss. With natural-log amplitude and epsilon 1e-7, amplitude loss combines frame Huber loss (delta 1), voiced-frame correlation loss (weight .3), consecutive-voiced-frame first-difference MSE (.2), and stride-eight mean-pooled log-amplitude MSE (.3). The legacy `per_crop_amp_norm` flag subtracts the SAME target voiced-log mean from prediction and target; it does not fit separate prediction gain. Exact masking and empty-crop rules are in `compute_baseline_loss`. All other optional loss terms are disabled in the frozen recipes.

Five references use the same folds. The gate is one on the union of annotated note frames and zero elsewhere; it has no fitted level. Global OLS and instrument OLS fit an intercept and the 20 frame features to log(max(target, 1e-7)) on training frames. Instrument OLS fits one regression per instrument, with global fallback. Note OLS regresses log(max(note mean, 1e-7)) on mean note features using training notes of at least four frames. Exponentiated predictions use the fixed numerical log bounds [-30, 10]. No bound was active in the retained outputs. Shared envelopes multiply those note levels by instrument-specific templates averaging mean-normalized training notes in 64 phase bins. Templates are interpolated and renormalized at the requested duration. Rendered notes of at least one frame contribute; overlapping contributions are averaged and unannotated frames are zero. These references test timing, feature-based levels and reusable shapes, not the complete score-feature basis model of prior performance research.

## 3. Metrics, coverage and uncertainty

All reported means weight tracks equally. Pearson correlation is undefined with fewer than three samples or standard deviation below 1e-10 in either array. Undefined values remain missing and their denominators are retained. Full-track correlation uses the complete cached horizon; active-frame correlation uses the union of annotated intervals.

For a note with times s,e and cached hop h, its frame interval is [max(0,int(s/h)), min(T,int(e/h))). The original integer truncation and cached floating-point h are preserved. Eligible primary notes have at least four frames. Across-note correlation compares the predicted and target means of these intervals. Within-note shape first correlates frames within each eligible note, then averages defined note correlations within the track. These two measures are not additive components of the full-track coefficient. Note-wise affine invariance refers to each interval's correlation, not to a physically separable decomposition of an overlapping waveform.

For domain/scale evaluation, apply either identity or ln(a+1e-7), then Gaussian smoothing to both prediction and target. Standard deviations are 0, .05, .1, .2, .5 and 1 seconds, converted using the cached hop; boundary mode is reflect and truncation is four standard deviations. Zero smoothing is identity. No prediction is refitted for a measurement condition. The main result uses all scales; no best-scale model selection is performed.

In the frozen legacy report, `rmse_log` means full-track log RMSE and `rmse_log_active` means active-frame log RMSE. In the new display/export dictionary these are explicitly named `full_log_rmse` and `active_log_rmse`; original report fields are retained unchanged for provenance. Linear RMSE is sqrt(mean((prediction-target)^2)); log RMSE replaces both arrays by ln(a+1e-7). Compute both on full tracks and active frames, then average tracks. No test-fitted gain or offset is used. Errors measure agreement in cached recording units, not perceptual quality. The main table uses log RMSE of note means; the four full/active frame-error views are supplied separately. Note OLS and shared envelopes have particularly large full-track log errors because their unannotated-frame predictions are zero while recorded tails need not be. The unit gate is an uncalibrated timing control, explaining its large error.

Paired intervals resample piece/duplicate groups with replacement, keeping every track of each sampled group, and recompute the equal-track mean difference. There are 5,000 draws, seed 20260911, with 2.5th/97.5th percentiles. Pair-specific defined coverage determines the group set. Intervals are pointwise and conditional on these fixed predictions, seed and folds; they do not measure training-seed variation, correct multiple comparisons or remove historical test-based development. They are descriptive precision checks for the studied predictors, not confirmatory tests of newly selected algorithms. A cross-zero interval neither establishes equivalence nor proves absence of improvement.

## 4. Post-review annotation and population checks

The dated `PROTOCOL.md` records these additional analyses before their computation, after reviewing earlier results. This is not preregistration. Predictions, folds and targets are unchanged. All positive-length annotations contribute to overlap detection, including notes shorter than the primary minimum. For the frame check, exclude an entire eligible note if any of its frames has multiplicity greater than one. For the independent continuous-time check, exclude both whole notes in every overlapping half-open time-interval pair, without quantization. No fragments are trimmed and no retained subset is chosen by scores.

Additional populations are whole tracks with no frame overlap; the previously frozen native single-lane population at the synthesis grid; exact-target deduplication; URMP; and all remaining corpora together. These definitions are distinct. All model means, coverage and planned paired comparisons are in `expected_results.json`, including unfavorable and positive exceptions. The small non-URMP subgroup is heterogeneous, so its contrast does not identify a causal corpus property.

## 5. Public synthesis systems

The public-system populations and frozen protocol JSON files are included separately. Neither public predictor uses MIDI velocity. The MIDI-DDSP expression input contains note pitch, note duration and instrument ID; original MIDI2Params receives frame pitches and onset/offset flags. Loudness/amplitude conditioning is generated by the respective predictor, not copied from the target recording. The supplied frozen protocol fields and inference adapters document these inputs. Original MIDI2Params uses the author-designated `best_model_cpu_120.pt` predictor and CustomViolin synthesis checkpoint on 46 violin tracks; it is not the MIDI-DDSP authors' reimplementation. Public MIDI-DDSP uses synthesis step 50000 and expression step 5000 on all 186 tracks. Both preserve absolute onsets on the 250 Hz synthesis grid, allocate overlapping notes to voices, and sum complete waveforms at unit gain. There is no score-based track trimming or gain selection. RMS is extracted from final 16 kHz audio, with window 320, hop 160, centered constant padding and the frozen target horizon. Seeds, tails, reverb and checkpoint hashes are in the supplied protocol files.

Public URMP pretraining may overlap the evaluation pieces. Neither pipeline was retrained on the internal folds. Public-system results describe fixed adapted pipelines and are not evidence of a fair architecture ranking or clean generalization. The companion also contains the already-collected final RMS arrays for all 186 MIDI-DDSP and 46 original MIDI2Params tracks, mapped to the same cached targets. Each source RMS file is checked against its original completion-record SHA-256. `verify_public_rms.py` uses NumPy/SciPy to recompute full, active, note-mean and within-note correlations plus log correlation and one-second log-smoothed correlation. It checks 1,392 per-track values, 36 public-subset means and 120 primary paired-bootstrap intervals against the frozen reports. These checks reproduce evaluation from archived final RMS, not waveform generation or RMS extraction from audio. No new prediction, gain fit, track selection or inference is performed.

## 6. Reproduction

Use Python with NumPy (verified with NumPy 2.4.3). From the extracted companion directory run `python verify.py`. It independently recomputes correlations, errors, overlap masks, 576 planned paired-bootstrap comparisons and fold group separation from the supplied arrays, checking against the stored results at tolerance 1e-8. It uses no GPU and does not read remote files. The independent implementation uses difference-array overlap counting and sorted-interval overlap detection rather than the original audit loops. `verification.json` reports its actual result. The additional `verify_level_audit.py` independently checks 4,464 note-error entries and 45 paired error/aggregation intervals using cumulative-sum interval means and explicit resampled group-row concatenation; its maximum difference is 1.78e-15. It does not import the original analysis implementation. `manifest.json` identifies the exact packaged files by SHA-256. Source files are supplied to clarify the original computation, including legacy options not enabled in this study; the frozen recipe files determine which options were used.

## 7. Low-variance interval check

`variance_audit.json` records target standard-deviation quantiles, per-track eligible/defined note-count distributions, and results for all eight predictors at thresholds 1e-8, 1e-6 and 1e-4. No eligible target interval has standard deviation below 1e-6; just one of 30,352 falls below 1e-4. Every neural model and the shared envelope has defined shape correlations on all primary eligible notes. Track note counts range from 24 to 777 (median 140.5, quartiles 57.5 and 219). Note OLS has 569 defined correlations across 53 tracks. The stricter 1e-4 target threshold changes neural shape means by less than 1.4e-5. Thresholds are in cached recording units, not perceptual thresholds. Arithmetic means of r describe a typical track; Fisher averaging or equal-note weighting would define a different estimand. Neither is silently substituted.

## 8. Note-level error and alternative aggregation

For each original eligible interval, average prediction and target separately. Note linear RMSE and MAE compare these means; note log RMSE compares ln(mean+1e-7), then takes a root mean square across notes. Finally average tracks equally. No test calibration is fitted. The main-table Error field is `note_log_rmse`, distinct from both `full_log_rmse` and `active_log_rmse`; their complete tables are retained. Correlation alone tests co-variation. Linear errors test numerical agreement in recording units; log differences are dimensionless predicted/target note-mean log ratios, with epsilon added before the ratio. They retain overall recording-gain mismatch because no gain is fitted.

The primary arithmetic mean of track correlations describes a typical instrument track without duration/note-count weighting. For sensitivity, average tracks inside each piece/duplicate group then average groups equally; alternatively clip track r to +/-[1-1e-7], take arctanh, average equally over tracks, then apply tanh. In each of 5,000 paired group-bootstrap draws (seed20260911), recompute the full estimator and difference. Fisher aggregation here changes the across-track aggregation, not the preceding arithmetic within-track note average. All planned comparisons and any interval-sign changes appear in the supplementary table and `level_and_aggregation_audit.json`. These exploratory alternatives do not replace the primary estimator. Run `python level_and_aggregation_audit.py` to reproduce them from the same arrays.

For the binary gate at zero smoothing, log(gate+epsilon) is a positive affine map of the two gate values. Its Pearson change under the joint log transformation therefore comes from the target transformation. After smoothing, the scale comparison also changes temporal resolution. This is an explanatory property of the specified measurement, not an additional experiment.
