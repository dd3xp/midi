# 训练策略

本文档描述模型训练的具体策略，包括数据划分、训练流程、超参数选择、损失函数设计和评估方案。

---

## 一、数据划分

### 1.1 划分原则

URMP 数据集中存在同一首曲子的不同乐器 track（例如 `08_Spring_fl_vn` 中 track1 是长笛、track2 是小提琴）。如果将同一首曲子的不同 track 分到训练集和测试集中，模型可能通过记住曲子的节奏/结构来"作弊"，导致评估指标虚高。因此划分以**曲目（piece）**为单位，而非以 track 为单位：同一首曲子的所有 track 要么全在训练集，要么全在测试集。

### 1.2 具体划分

按曲目划分为训练集（~80%）和测试集（~20%），每种乐器都需要在测试集中有足够的样本（至少 3-5 个 track）以支撑分乐器的指标统计。不设验证集——数据量有限，用训练损失的下降趋势和过拟合监控代替验证集的功能。

现有数据概况（74 tracks，3 种乐器）：

| 乐器 | Tracks | 总时长 | 音符数 |
|------|--------|--------|--------|
| Violin (vn) | 34 | ~3400s | ~7200 |
| Trumpet (tpt) | 22 | ~2600s | ~4200 |
| Flute (fl) | 18 | ~2100s | ~4400 |

### 1.3 数据增强

训练数据 135 分钟虽然绝对量不大，但帧级样本有 ~810K 帧，配合以下增强手段可以进一步缓解过拟合：

- **随机裁剪**：训练时从完整 track 中随机裁剪固定长度的片段（如 512 帧 = 5.12 秒），而非使用完整序列。这既增加了样本多样性（同一 track 每次裁剪的起始位置不同），又统一了 batch 内的序列长度，便于 GPU 并行计算。
- **Pitch shift（可选）**：将整段的 MIDI pitch 和 f0 同时上移或下移 1-2 个半音。这不改变演奏表达（颤音深度、力度变化等），但增加了音高维度的多样性。需要注意不要超出乐器的合理音域。
- **时间拉伸（暂不使用）**：改变 tempo 会影响颤音速率和包络形状，可能引入不自然的训练信号，暂不采用。

## 二、训练流程

### 2.1 分阶段训练

参考 MIDI-DDSP [Wu et al., 2022] 的自底向上训练策略，本项目也采用分阶段训练，但只有两个阶段（因为不包含 DDSP 合成器层）：

**阶段 1：训练 MIDI Encoder + Baseline 模型**

先训练 baseline 模型（MIDI Encoder + BiGRU 预测头），目的有二：
1. 验证 MIDI Encoder 的特征编码是否有效——如果 baseline 在训练集上都学不好，说明编码方式有问题
2. 得到一个可用的 baseline 结果，作为后续扩散模型的对比基准

训练 baseline 时，MIDI Encoder 和 BiGRU 预测头端到端联合训练。

**阶段 2：训练条件扩散模型**

冻结阶段 1 训练好的 MIDI Encoder（不更新其参数），只训练 1D U-Net 去噪网络。冻结 Encoder 的原因：
- 保证 baseline 和扩散模型使用完全相同的条件特征 C(t)，对比实验更公平
- 减少训练参数量，加速收敛
- MIDI Encoder 已经在阶段 1 被验证过有效

如果阶段 2 效果不佳，可以解冻 Encoder 进行端到端微调，但需要同时更新 baseline 的结果以保持公平对比。

### 2.2 为什么不端到端一起训练

如果将 MIDI Encoder 和扩散模型端到端训练，存在两个问题：第一，扩散模型的损失是噪声预测的 MSE，梯度信号比较弱（尤其在训练早期），可能不足以有效训练 Encoder。第二，端到端训练使得 Encoder 和扩散模型的表示空间耦合在一起，不利于调试和分析——如果效果不好，很难判断是 Encoder 的问题还是去噪网络的问题。分阶段训练将这两个问题解耦。

## 三、超参数

### 3.1 MIDI Encoder + Baseline

| 超参数 | 值 | 说明 |
|--------|-----|------|
| Encoder 线性层维度 | 128 | 7 维 → 128 维 |
| Encoder BiGRU 隐藏维度 | 128 | 输出 256 维（双向拼接） |
| Baseline BiGRU 隐藏维度 | 256 | 输出 512 维 |
| f0 分类 bin 数 | 81 | ±200 cents / 5 cents + 1 unvoiced |
| Dropout | 0.3 | 在 GRU 层之间 |
| 学习率 | 1e-3 | Adam optimizer |
| 学习率调度 | ReduceLROnPlateau | patience=5, factor=0.5 |
| Batch size | 32 | 每个样本 512 帧 |
| 训练轮数 | 100 epochs | 配合 early stopping（patience=15） |
| 损失权重 λ | 1.0 | L = L_CE(f0) + λ · L_MSE(amp)，需调参 |

### 3.2 条件扩散模型

| 超参数 | 值 | 说明 |
|--------|-----|------|
| 扩散步数 T | 1000 | 标准 DDPM |
| 噪声调度 | cosine | 比 linear 在低噪声区更平滑 [Nichol & Dhariwal, 2021] |
| U-Net 通道数 | [128, 256, 512] | 三层下采样 |
| ResBlock 数 / 层 | 2 | 每个下/上采样块内 |
| Attention 层 | 前两层有，最深层无 | 最深层序列太短，attention 收益低 |
| 时间步嵌入维度 | 256 | 正弦编码 + 2 层 MLP |
| 学习率 | 2e-4 | Adam, β₁=0.9, β₂=0.999 |
| EMA decay | 0.9999 | 指数移动平均，用于推理 |
| Batch size | 16 | 每个样本 512 帧 |
| 训练轮数 | 200 epochs | 扩散模型通常需要更长训练 |
| 推理采样步数 | 50 | 使用 DDIM 加速 |

### 3.3 超参数选择依据

- **学习率**：baseline 用 1e-3 是 Adam 的常用默认值；扩散模型用 2e-4 参考了 DDPM 原始论文 [Ho et al., 2020] 的设置，扩散模型通常需要较小的学习率以保证训练稳定。
- **Cosine 噪声调度**：Nichol & Dhariwal [2021] 发现 cosine 调度在小数据集和低分辨率任务上优于 linear 调度，因为 linear 调度在低噪声区变化太快，模型难以学到细节。本项目的 f0+amp 信号分辨率不高（2 通道），属于这一适用场景。
- **EMA**：指数移动平均是扩散模型训练的标准做法，用训练参数的滑动平均做推理，生成质量更稳定。
- **512 帧裁剪长度**：对应 5.12 秒，足够覆盖 2-5 个音符及其上下文，同时不会导致序列过长增加计算负担。

## 四、损失函数详细设计

### 4.1 Baseline 损失

$$L_{baseline} = L_{CE}(f0) + \lambda \cdot L_{MSE}(amp)$$

**f0 交叉熵损失 $L_{CE}$**：

对每个 voiced 帧（is_voiced=1），计算 81 类分类的交叉熵。unvoiced 帧不参与 f0 损失计算——这参考了开题报告 §5.2 的设计（"在无声段不监督 f0"），避免模型在无声段学到无意义的 f0 值。

具体地：将 ground truth f0 转换为相对于当前音符 MIDI 音高的 cent 偏移，量化到最近的 bin（±200 cents 范围内每 5 cents 一个 bin）。超出 ±200 cents 的帧 clip 到边界 bin。unvoiced 帧的目标 bin 为第 81 个（unvoiced 类）。

**amp MSE 损失 $L_{MSE}$**：

对所有帧计算预测 amp 与 ground truth amp 的均方误差。amp 在计算损失前取 log 变换，因为人耳对响度的感知接近对数尺度（Weber-Fechner 定律），log 空间的 MSE 更符合感知上的误差分布。

**损失权重 λ**：

f0 交叉熵的量级（通常 1-4）和 amp MSE 的量级（通常 0.01-0.1）差异较大，需要 λ 来平衡。初始设 λ=1.0，通过观察两个损失分量的下降曲线来调整：如果一个分量收敛很快而另一个停滞，适当增大停滞分量的权重。

### 4.2 扩散模型损失

$$L_{diffusion} = \mathbb{E}_{t, x_0, \epsilon} \left[ \| \epsilon - \epsilon_\theta(x_t, t, C) \|^2 \right]$$

这是标准的 DDPM 噪声预测损失 [Ho et al., 2020]，不需要额外的加权或辅助损失。

实际训练时，每个 batch 内的操作为：
1. 从训练集采样一批 (MIDI, f0, amp) 三元组
2. 对 f0 和 amp 做归一化（§model.md 5.5.4 所述）
3. 对每个样本随机采样时间步 t ~ Uniform{1, ..., T}
4. 随机生成噪声 ε ~ N(0, I)
5. 计算 x_t = √ᾱ_t · x₀ + √(1-ᾱ_t) · ε
6. 用 U-Net 预测 ε̂ = ε_θ(x_t, t, C)
7. 损失 = MSE(ε̂, ε)

### 4.3 是否需要额外损失

MIDI-DDSP [Wu et al., 2022] 在其确定性 Synthesis Generator 中使用了对抗损失来对抗过度平滑。本项目的扩散模型**不需要对抗损失**，因为扩散模型本身就在建模分布而非点估计，从根本上避免了均值坍缩的问题。

可选的辅助损失（如果基础方案效果不够好再考虑）：
- **重建损失**：在扩散损失之外，加一个对 x₀ 的直接重建损失，加速模型学习大尺度结构
- **频谱损失**：将预测的 f0 合成简单正弦波，与 ground truth 正弦波做多尺度频谱损失，引入频域约束

## 五、评估方案

### 5.1 保真度指标（与 ground truth 对比）

这些指标逐帧对比预测与 ground truth，衡量生成质量。

**f0 指标：**

| 指标 | 计算方法 | 说明 |
|------|---------|------|
| RPA (Raw Pitch Accuracy) | voiced 帧中 \|pred - gt\| < 50 cents 的比例 | 音高整体准确率，阈值 50 cents 是半音，参考 mir_eval 的标准定义 |
| f0 MAE (cents) | voiced 帧的平均绝对 cent 误差 | 音高偏差的平均幅度 |
| VDE (Vibrato Depth Error) | 对每个长音（>0.3s）提取颤音深度（f0 振荡幅度的半峰值），计算预测与真实的绝对误差 | 颤音深度是否合理 |
| VRE (Vibrato Rate Error) | 对每个长音提取颤音频率（f0 振荡的主频率），计算预测与真实的绝对误差 | 颤音速率是否合理 |

颤音的提取方法：对音符内的 f0 轨迹减去线性趋势后做 FFT，取 4-8Hz 范围内的最大峰作为颤音频率，该峰的幅度作为颤音深度。

**amp 指标：**

| 指标 | 计算方法 | 说明 |
|------|---------|------|
| Envelope Correlation | 预测与真实 amp 序列的皮尔逊相关系数 | 力度轮廓吻合度，本项目数据预处理阶段已用此指标验证数据质量（平均 0.990） |
| Amp RMSE | 均方根误差（log 空间） | 绝对幅度的偏差 |

**对于扩散模型**：每个测试样本采样 N=10 次，报告两个数字：
- **Oracle**：N 次中与 ground truth 最接近的那次（取 f0 MAE 最低的采样），代表"模型能做到多好"
- **Mean**：N 次的平均指标，代表"模型通常做到多好"

### 5.2 合理性指标（统计特征对比）

这些指标不逐帧对齐，而是比较**分布级别**的统计特征，更适合评估随机生成模型。

| 指标 | 计算方法 | 说明 |
|------|---------|------|
| Vibrato Rate Distribution | 统计所有长音的颤音频率，与真实分布做 KL 散度 | 颤音速率分布是否合理（真实通常集中在 4-7Hz） |
| Vibrato Depth Distribution | 统计所有长音的颤音深度，与真实分布做 KL 散度 | 颤音深度分布是否合理 |
| Dynamic Range | 每首曲子 amp 的 90 分位与 10 分位之比 | 力度对比是否合理 |
| FAD (Frechet Audio Distance) | 将 f0+amp 通过 synthesize.py 合成音频，计算合成音频与真实音频的 FAD | 整体音频质量的感知级指标 |

### 5.3 多样性指标（扩散模型独有）

| 指标 | 计算方法 | 说明 |
|------|---------|------|
| f0 Inter-sample Std | 同一 MIDI 采样 10 次，逐帧计算 f0 的标准差，然后取均值 | 生成的表达多样性有多大 |
| Amp Inter-sample Std | 同上，对 amp 计算 | 力度变化的多样性 |
| 与真实多样性对比 | 如果 URMP 中有多人演奏同一曲目，计算真实演奏间的 f0 std | 生成的多样性是否与真实接近 |

如果多样性过大（远超真实），说明模型没有充分利用 MIDI 条件；如果多样性为零，说明模型退化为确定性预测，扩散没有起到作用。

### 5.4 听觉评估（可选）

将 f0+amp 通过已有的 `synthesize.py` 合成音频，进行主观评测：

- **AB Preference Test**：给听者播放 baseline 和 diffusion 的合成结果（随机顺序），问"哪个听起来更自然"
- **MOS (Mean Opinion Score)**：1-5 分评价自然度
- 听者数量：至少 5-10 人，不需要专业音乐训练
- 测试曲目：从测试集中选取 5-10 段，覆盖三种乐器

对于 AIMC 论文，如果时间不够，听觉评估可以省略，但如果能做会大幅增强说服力。

### 5.5 报告方式

所有指标按乐器（violin / trumpet / flute）分别报告，同时报告三种乐器的加权平均（按 track 数加权）。在论文中以表格呈现保真度指标（实验 1），以图示呈现多样性分析（实验 2）和可视化案例（实验 3）。

## 六、训练监控与调试

### 6.1 训练过程中需要监控的量

**Baseline：**
- 训练/测试 f0 交叉熵（应持续下降，测试集不应发散）
- 训练/测试 amp MSE
- 每 N epoch 在测试集上计算 RPA 和 Envelope Correlation

**扩散模型：**
- 训练损失（噪声预测 MSE，应持续下降但最终会收敛到一个非零值）
- 每 N epoch 采样几段测试样本，可视化 f0+amp 曲线，直观判断质量
- EMA 模型的损失应低于非 EMA 模型

### 6.2 常见问题与对策

| 问题 | 表现 | 对策 |
|------|------|------|
| f0 预测为常数（均值坍缩） | RPA 很低，f0 曲线几乎是直线 | 检查 f0 归一化是否正确；增大 dropout |
| amp 全为零或常数 | Envelope Correlation ≈ 0 | 检查 amp 归一化；调整损失权重 λ |
| 扩散模型生成噪声 | 采样结果看不出任何结构 | 训练轮数不够；检查条件注入是否正确（C(t) 是否被用到） |
| 扩散模型过度平滑 | 采样结果有结构但没有颤音 | 增加训练轮数；检查 U-Net 是否有足够容量 |
| 过拟合（训练好测试差） | 训练 RPA 高但测试 RPA 低 | 增大 dropout；增强数据增强；减小模型 |

### 6.3 Checkpoint 保存策略

- 每 10 epoch 保存一次 checkpoint
- 保留测试集 RPA 最高的 checkpoint（baseline）
- 保留训练损失最低的 EMA checkpoint（扩散模型）
- 最终评估使用最佳 checkpoint

## 七、计算资源估算

| 阶段 | 模型 | 预估训练时间（单 GPU） |
|------|------|----------------------|
| 阶段 1 | MIDI Encoder + Baseline | 1-2 小时（模型小，数据小） |
| 阶段 2 | 条件扩散模型 | 4-8 小时（模型更大，epoch 更多） |
| 评估 | 扩散采样 10 次 × 测试集 | 0.5-1 小时（DDIM 50 步） |

以上基于单块中端 GPU（如 RTX 3060/3070）的估算。如果使用 CPU，时间约为 5-10 倍。
